# ТЗ: согласование статей и оформления блога в кабинете биржи лидов

## Зачем

У каждого клиента на сайте есть блог со статьями для SEO (1 статья в неделю). Клиент не работает ни с GitHub, ни с Telegram-кнопками. Он заходит в свой кабинет на бирже лидов и там:

1. один раз согласовывает **оформление** блога;
2. согласовывает **статьи** по одной.

Публикация целиком на нашей стороне: как только клиент согласовал, всё остальное происходит автоматически (дата выхода, публикация на сайте, карта сайта, отправка в Яндекс и Bing).

**У клиента только кнопки «Согласовать».** Полей для комментариев, кнопок «Отклонить» и «Предложить изменения» нет. Если клиент не нажал, статья просто ждёт.

## Что видит клиент (раздел «Блог» в кабинете)

**Блок 1. «Оформление блога»** (показывается, пока `design_approved = false`)
- Ссылка «Посмотреть, как будет выглядеть блог» (`design_preview_url`), открывается в новой вкладке.
- Кнопка **«Согласовать оформление»**.
- После нажатия блок исчезает, появляются статьи.
- Пока оформление не согласовано, статьи не публикуются.

**Блок 2. «Статьи на согласовании»** (список `awaiting`)
- Для каждой: заголовок, короткое описание, время чтения, ссылка «Прочитать» (`preview_url`, новая вкладка).
- Кнопка **«Согласовать»**. После нажатия статья уходит из списка и попадает в «Запланировано».

**Блок 3. «Запланировано»** (`scheduled`): заголовок и дата выхода.

**Блок 4. «Опубликовано»** (`published`): заголовок, дата, ссылка на статью на сайте.

## Откуда брать данные

Публичный JSON на сайте клиента, авторизация не нужна:

```
GET {siteUrl}/blog/queue.json
```

Пример:

```json
{
  "site": "https://murzzsite.github.io/dom-design-mebel",
  "updated": "2026-09-30",
  "design_approved": false,
  "design_preview_url": "https://.../blog/preview/83b08c74a5e9/",
  "awaiting": [
    { "slug": "kuhnya-6-metrov", "path": "articles/kuhnya-6-metrov.md", "title": "…", "description": "…", "reading_time": "3 мин чтения", "preview_url": "https://.../blog/preview/152d60a640a5/kuhnya-6-metrov/" }
  ],
  "scheduled": [ { "slug": "…", "title": "…", "date": "2026-10-07" } ],
  "published": [ { "slug": "…", "title": "…", "url": "https://…", "date": "2026-09-23" } ]
}
```

`queue.json` обновляется после каждой сборки сайта (обычно через 1–2 минуты после действия). Сразу после нажатия кнопки кабинет может показать новое состояние без ожидания, а при следующей загрузке брать данные из JSON.

## Действия (кабинет биржи вызывает наш Worker)

Базовый адрес: `https://lead-relay.leestygpt.workers.dev`
Авторизация: заголовок `Authorization: Bearer <API_KEY>` (выдаётся программисту отдельно).

**Важно: вызовы делает сервер кабинета, не браузер клиента.** Ключ не должен попадать в страницу.

| Действие | Запрос | Тело |
|---|---|---|
| Согласовать статью | `POST /blog/approve` | `{"repo":"murzzsite/<repo>","path":"articles/<файл>.md"}` (`path` берётся из `awaiting[].path`) |
| Согласовать оформление | `POST /blog/approve-design` | `{"repo":"murzzsite/<repo>"}` |
| Отправить сайт в индекс | `POST /seo/index` | `{"repo":"murzzsite/<repo>"}` |

Ответы: `200 {"ok":true}`; повторный вызов безопасен (`"already":true`). Ошибки: `401` неверный ключ, `400` неверные параметры, `502` ошибка GitHub (показать «Не получилось, попробуйте ещё раз позже»).

## Привязка клиента к сайту

В карточке клиента нужны два поля:
- `site_url` (адрес сайта, например `https://murzzsite.github.io/dom-design-mebel`), для чтения `queue.json`;
- `repo` (например `murzzsite/dom-design-mebel`), для вызовов Worker.

## Автоматическая индексация сайтов клиентов

- **После каждой публикации** сайт сам отправляет новые страницы в Яндекс и Bing (протокол IndexNow), участие кабинета не нужно.
- **Для менеджера** в карточке клиента нужна кнопка **«Отправить сайт в индекс»** (`POST /seo/index`): отправляет в Яндекс и Bing все страницы из `sitemap.xml`. Использовать после подключения сайта и после крупных изменений. Ответ: `{"ok":true,"urls":N,"results":{"yandex.com":200,"www.bing.com":200}}`.
- Google так получить страницы не может: у него нет аналога IndexNow. Для Google сайт один раз добавляется в Search Console и подаётся `sitemap.xml`. Это ручной шаг из чек-листа.

## Что важно сохранить

- Никаких форм для комментариев и «правок» у клиента.
- Статьи и оформление публикуются только после согласования клиентом.
- Уведомление менеджеру о том, что клиент согласовал статью или оформление, через бота (по желанию, отдельная настройка).
- Одна статья в неделю: график выставляет сайт сам, кабинет даты не назначает.

## Проверка

1. Клиент в кабинете нажимает «Согласовать оформление». Через 1–2 минуты в `queue.json` `design_approved` становится `true`, на сайте появляется ссылка «Блог» в меню.
2. Клиент нажимает «Согласовать» под статьёй. Через 1–2 минуты статья переезжает из `awaiting` в `scheduled`, в назначенный день появляется на сайте.
3. Кнопка «Отправить сайт в индекс» возвращает `200` от Яндекса и Bing.

## Зависимости

- Сайт клиента подключён к блогу (`seo-blog-kit`), в репозитории есть `blog.config.json` (с `designApproved: false` для новых клиентов).
- В Worker задан секрет `GITHUB_TOKEN`, а в репозитории клиента лежит файл автоматизации GitHub (нужны права `workflow`), иначе публикация по расписанию не запустится.
