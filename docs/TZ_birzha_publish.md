# ТЗ: публикация статей блога из кабинета биржи лидов

## Зачем

У каждого клиента на сайте есть блог со статьями для SEO (1 статья в неделю). Оформление блога уже есть в оформлении сайта, которое клиент согласовал при сдаче сайта, отдельно его согласовывать не нужно.

В кабинете клиента на бирже нужен раздел «Блог», где клиент **только нажимает «Опубликовать»** под каждой статьёй. Остальное происходит автоматически: дата выхода, публикация на сайте, обновление карты сайта, отправка в Яндекс и Bing. Публикация целиком на нашей стороне.

У клиента одна кнопка: **«Опубликовать»**. Больше ничего: ни полей для текста, ни других кнопок.

## Что видит клиент (раздел «Блог»)

1. **«Готовы к публикации»** (список `awaiting`): заголовок, короткое описание, время чтения, ссылка «Прочитать» (`preview_url`, открывается в новой вкладке) и кнопка **«Опубликовать»**. После нажатия статья уходит из списка в «Запланировано» (выйдет на сайте по графику).
2. **«Запланировано»** (`scheduled`): заголовок и дата выхода.
3. **«Опубликовано»** (`published`): заголовок, дата, ссылка на статью на сайте.

Если файла `queue.json` нет (404), показать «Блог пока не подключён».

## Откуда брать данные

Публичный JSON на сайте клиента, авторизация не нужна:

```
GET {site_url}/blog/queue.json
```

Пример:

```json
{
  "site": "https://murzzsite.github.io/dom-design-mebel",
  "updated": "2026-09-30",
  "awaiting": [
    { "slug": "kuhnya-6-metrov", "path": "articles/kuhnya-6-metrov.md", "title": "…", "description": "…", "reading_time": "3 мин чтения", "preview_url": "https://.../blog/preview/152d60a640a5/kuhnya-6-metrov/" }
  ],
  "scheduled": [ { "slug": "…", "title": "…", "date": "2026-10-07" } ],
  "published": [ { "slug": "…", "title": "…", "url": "https://…", "date": "2026-09-23" } ]
}
```

`queue.json` обновляется после каждой сборки сайта (обычно через 1–2 минуты после действия). Сразу после нажатия кнопки кабинет сам показывает новое состояние (статья переехала в «Запланировано»), не дожидаясь обновления файла.

## Действие (кабинет биржи вызывает наш Worker)

Базовый адрес: `https://lead-relay.leestygpt.workers.dev`
Авторизация: заголовок `Authorization: Bearer <API_KEY>` (ключ выдаётся программисту отдельно).

**Важно: вызовы делает сервер кабинета, не браузер клиента.** Ключ не должен попадать в страницу.

| Действие | Запрос | Тело |
|---|---|---|
| Опубликовать статью (кнопка клиента) | `POST /blog/approve` | `{"repo":"murzzsite/<repo>","path":"articles/<файл>.md"}` (`path` берётся из `awaiting[].path`) |
| Отправить сайт в индекс (кнопка только для менеджера) | `POST /seo/index` | `{"repo":"murzzsite/<repo>"}` |

Ответы: `200 {"ok":true}`; повторный вызов безопасен (`"already":true`). Ошибки: `401` неверный ключ, `400` неверные параметры, `502` ошибка GitHub, `500` не настроен токен на нашей стороне. Клиенту любая ошибка показывается как «Не получилось, попробуйте позже», подробности только в логе сервера.

## Привязка клиента к сайту

В карточке клиента два поля, которые заполняет менеджер:
- `site_url` (например `https://murzzsite.github.io/dom-design-mebel`), для чтения `queue.json`;
- `repo` (например `murzzsite/dom-design-mebel`), для вызовов Worker.

## Автоматическая индексация сайтов клиентов

- **После каждой публикации** сайт сам отправляет новую страницу в Яндекс и Bing (IndexNow), участие кабинета не нужно.
- **Для менеджера** в карточке клиента кнопка **«Отправить сайт в индекс»** (`POST /seo/index`): отправляет в Яндекс и Bing все страницы из `sitemap.xml`. Ответ: `{"ok":true,"urls":N,"results":{"yandex.com":200,"www.bing.com":200}}`. Использовать после подключения сайта.
- Google так получить страницы не может, для него сайт один раз добавляется в Search Console (ручной шаг из чек-листа).

## Безопасность

- Ключ API хранится только на сервере кабинета, в переменной окружения; в логи заголовок `Authorization` не писать.
- Клиент может опубликовать только свою статью: `repo` и `path` берутся из его карточки и из его `queue.json`, а не из запроса браузера.
- Кнопка «Отправить сайт в индекс» доступна только менеджеру.

## Проверка

1. Страница «Блог» показывает статьи из `queue.json` тестового клиента (`site_url` = `https://murzzsite.github.io/seo-blog-demo`, `repo` = `murzzsite/seo-blog-demo`).
2. Кнопка «Опубликовать» вызывает `POST /blog/approve`. Через 1–2 минуты статья переезжает из `awaiting` в `scheduled`, в назначенный день появляется на сайте.
3. «Отправить сайт в индекс» возвращает `200` от Яндекса и Bing.

## Зависимости на нашей стороне

- Сайт клиента подключён к блогу (`seo-blog-kit`).
- В Worker задан секрет `GITHUB_TOKEN`, а в репозитории клиента лежит файл автоматизации GitHub (нужны права `workflow`). До этого метод публикации отвечает `500`, это не ошибка кабинета.
